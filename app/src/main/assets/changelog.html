1.2.4 — Downloads page fix

UI

  • Menu → Downloads opens the downloads page in a new tab instead of reloading the current one.
  • About → Latest available version reads the releases list and picks the highest published semver — GitHub's /releases/latest pointer can lag (showed "1.2.0" while 1.2.4 was out).
  • Downloads: a native Downloads screen (system DownloadManager + app store) replaces the generated HTML page — real entries, Open / Retry per item, Clear all.
  • Downloads screen rows follow browser-native UX — icon, full file name, a size + source-domain subtitle, and a per-row overflow menu (Open / Retry / Share file / Share URL / Rename / Delete).
  • Downloads gains an browser-style Download Settings page (gear icon): default-location display, a delete policy (delete from device / remove from history / ask each time), and a 'Manage downloads with another app' toggle that opens the system downloads UI.
  • Downloads list is grouped into date buckets (Today / Yesterday / Last 7 days / Last 30 days / Older) with the download time in each row's subtitle.
  • Fixed the dark-page-on-reopen bug: a reopened-but-empty session never painted so the cold-start cover held dark until a tab switch — stale-load recovery now runs after each session bind.
  • Status bar fix: an aborted/abnormal video-fullscreen exit left the flags latched so the bar stayed hidden — the restore now runs before the early exit. (The 'Hide status bar while browsing' toggle already exists under Customize.)
  • Status bar readability (Android 15): the root now pads by the status-bar inset and icon contrast follows the theme — the bar reads like stock instead of icons faintly floating over page content. — pre-Android-15 devices already reserve the bar area, so the pad only applies on 35+ and no empty band appears.
  • Status bar band: stacked fitsSystemWindows consumed the bar inset again under the decor-reserved area — removed from the content chain (the empty strip under the icons is gone).
  • Tab drawer band + Settings title: removed the remaining drawer fitsSystemWindows; the settings toolbar now pads by the status-bar inset on Android 15+ so the title isn't clipped.
  • History restyled browser-like: date buckets, host + visit-time subtitle; Downloads/Download-Settings/History toolbars all pad for the status bar on Android 15+.
  • History reworked : per-day date headers, letter tiles per host, single-line title+URL, per-row delete, toolbar clear-all; subtitles no longer wrap; toolbar pads moved to parents (fixed clipped titles).
  • History: Recently-closed-tabs section, 'Time range to delete' dialog on the trash icon (last hour / today+yesterday / everything), history-specific dialog text.
  • Bookmark folders are real entities now (bookmark_folder table in the Rust store) — empty folders work; the drawer's folder button creates them directly. Sort: newest/oldest/A-Z/Z-A. Reading-mode proxy crash fixed.
  • Browser root now pads for the nav bar on Android 15+ — bottom buttons no longer sit under the virtual nav row.
  • History: browser-style time-range dialog; entries open in a new tab.
  • Downloads page: entries were never recorded when the download-meta persist threw ahead of the list write — the list is now populated; each item gets a Retry row and there's a Clear downloads list action plus an empty state; a failing store read degrades to the empty state instead of a blank tab.
  • Gecko autofill: browser.formfill.enable and extensions.formautofill.heuristics.enabled stay enabled outside incognito, and the GeckoView is now marked importantForAutofill — geckoview-158's setAutofillEnabled never did that, so Android's autofill framework skipped the view entirely (Bitwarden saw no fields, no context-menu entry).
  • Downloads: the post-completion integrity retry deleted the finished file before re-enqueueing — a failed re-queue left no file and a dead notification; the partial is now only dropped once a retry is in flight. The download request's MIME also falls back to the file extension when the server reports octet-stream, so the finished-download notification opens the file.
  • Gecko restore: an upgrade could "reproduce" an empty SessionState and commit about:blank, overwriting the tracked URL — the first tab then reloaded the blank and lost its title; blank commits before any real document no longer clobber the tracked URL. A generated-page load can also arrive before the session opens (silent drop → untitled empty tab) — loads now open the session first; the list read also has a 3s timeout so a wedged store call degrades to the empty state instead of a blank tab.
  • Settings: the fragment container now pads for the navigation-bar inset — the last rows of settings screens sat under the system nav bar in edge-to-edge mode.

1.2.1 — Download crash fix + crash log sharing

Engine

1.2 — Passwords

Engine

  • Saved-password support on both engines: submitting a login now offers a "Save password?" prompt, saved credentials autofill on revisit (single match fills directly, multiple accounts get a chooser), and clearing form/all web data wipes the store. Gecko ("full") provides the storage delegate GeckoView requires; WebView ("light") uses a secure postMessage login bridge, since importantForAutofill alone only reaches external autofill services.
  • Logins persist encrypted at rest (Android Keystore–wrapped AES-GCM file), never in private-mode sessions: incognito neither prompts nor fills.
  • The "Save passwords" privacy toggle gates the save prompt; the system-autofill path added in 1.1 stays active alongside for devices with an autofill service configured.

1.1 — Stability & maintenance release

Engine

  • GeckoView pinned to the stable release channel (the unsuffixed geckoview artifact); the 158.0.2 bump was reverted to the verified 158.0.1 build after it regressed background-tab restore.
  • Restore recovery uses its own abort signal instead of trusting engine callbacks — a tab whose load was killed without an onPageStop still recovers on select.
  • Tab titles persist in saved state and are reapplied on restore, so the tab strip shows the page name before its reload commits.
  • Gecko video fullscreen follows the Fenix model — gecko renders the fullscreen element inside the existing view, so the shell hides chrome instead of reparenting; fixes the reparent crash plus whitespace/truncation.
  • Update check: a daily GitHub Releases lookup (opt-out in General settings; incognito never checks) announces a newer tag once via dialog — Download opens the release page.

Privacy & permissions

  • Site-permission grants are covered by the engine storage model: clearing web storage now wipes remembered geolocation, notification, autoplay, camera and microphone decisions on both engines.
  • New "Site permissions" row in Privacy settings lists every stored per-origin grant with per-origin removal and a clear-all action.

Networking

  • Cleartext/network-security audit: plain HTTP stays permitted (a browser must load http:// sites), the manifest policy is documented, and the Force-HTTPS warning path covers the risk.

Persistence & restore

  • Tab restore treats the plain URL list as authoritative — engine session state is applied opportunistically on top, so an engine-upgrade-incompatible bundle can never white-screen a tab.
  • Regression tests cover the save→kill→restore path: aborted background restores re-issue their URL instead of staying blank.

Architecture & modernization

  • Tab-view swapping and fullscreen plumbing extracted from BrowserActivity into a dedicated controller — smaller blast radius for display/tab changes.
  • Deprecated-API sweep: typed getParcelable calls, modern display-metrics lookup, OnBackPressedDispatcher and the Activity Result API replace deprecated surfaces.
  • Adblock subscription staleness verified — lists refresh on the documented cadence.
  • Android Autofill framework integration so system password managers can fill and save through the browser (WebView opt-in; GeckoView's built-in AndroidAutofillDelegate) — disabled on incognito pages on both engines.

1.0 — Arktos Mobile: first release

Rebrand & project

  • Rebranded from SmartCookieWeb to Arktos Mobile — new package, Arktos icon set in every density and flavor, neutral defaults replacing dead hosted services.
  • Engine-coupling audit groundwork for a possible future selectable-engine effort.
  • Known Android WebView platform limits documented honestly in LIMITATIONS.md.

Rust core

  • New Rust core (arktos-core via UniFFI): unified ad/malware/site-block/LAN request engine, one verdict per request.
  • Storage moved to a single Rust database (ArktosStore) replacing five separate databases.
  • Search suggestions, userscript parsing, download filename rules, bookmark import/export, reader mode and URL utilities run in Rust.
  • Multi-list adblock subscriptions with a desktop-style filter & rank list manager under Privacy settings.
  • Tranco + Majestic site-rank lists, consent-gated, powering site-rank features.
  • App-lock and parental passwords hashed with argon2id, upgrading legacy entries in place.
  • Store schema v3 adds userscript run-at/no-frames columns and GM_*Value persistence.

  • AMOLED theme: the active tab is now distinguishable in the drawer (#298).

  • 'Follow system' dark mode for browser theme and the dark-web addon (#251).
  • One-tap new tab in drawer mode (#299); option to swap tabs/bookmarks icons (#297).
  • Downloads verify integrity, retry truncated transfers, resolve real filenames instead of .bin, and warn when a page is served instead of a file (#270/#311/#303).
  • Error pages no longer overwrite the tab's real URL (#281); first tap after returning to the app navigates correctly (#309).
  • SSL warnings limited to one per page load (#296); links prefer installed apps over the store (#316); picture links no longer crash (#306).
  • App-lock prompt survives a mistyped password (#302); per-site JavaScript/cookie quick-toggles (#305).
  • Dedicated 'No internet connection' page when offline (#323); forced SafeSearch for parental controls (#327).
  • Translation rebuilt on a configurable LibreTranslate-compatible endpoint (#300).
  • WebView Safe Browsing channel disabled; reader-mode and proxy bypass leaks fixed.
  • Userscript engine rebuilt on document-start injection with a real GM bridge — @run-at/@exclude/@require honoured, GM_xmlhttpRequest and GM.* APIs implemented.

Interface

  • This changelog — readable in-app here and maintained in the repo root ChangeLog file.

  • Tabs drawer header offers close-all / close-others; closing the last tab leaves a fresh default tab instead of exiting.

Settings & stability

  • Every settings screen audited: dead toggles wired up or removed, validation added where bad input could persist (download path, manual proxy, custom search URL — https only).
  • Import/export rebuilt on the Storage Access Framework: typed settings round-trip, content-sniffed bookmark formats, working tab backup/restore.
  • Parental-control lockout fixed; all password fields now mask input.
  • Tab sessions restore in order, save-state failures are handled, and a corrupt session can't leave the browser with zero tabs.
  • RxJava 3 migration, targetSdk 35, deprecated news feed removed.

Security

  • Browser-wide app lock — PIN, password, or biometric unlock, with a configurable re-lock timer (immediately, 1/5/10 min, or custom).
  • Password-encrypted backup archives (PBKDF2 + AES-256-GCM) in Settings → Import/Export; restore needs the password.
  • Auto Backup no longer carries the browsing database in plaintext — history/bookmarks/downloads only leave the device via the encrypted archive.

Search suggestions

  • Provider list rebuilt: Baidu and Naver removed; Startpage and Qwant added — all providers are HTTPS.
  • New installs default to DuckDuckGo; choices for removed providers migrate to DuckDuckGo instead of switching to Google.
  • Qwant requests use the device locale (e.g. de_DE, pt_BR) instead of a hardcoded en_US.

Security (continued)

  • Mixed content blocked by default; Force HTTPS warns on cleartext navigations instead of silently upgrading.
  • Translation bridge reduced to a postMessage surface; the userscript GM bridge enforces @connect domains.
  • Incognito windows can't be screenshotted or previewed in recents; optional secure-window toggle for the whole app; dialogs hardened against tapjacking overlays.
  • Exported components and incoming intents audited; the panic trigger sits behind a privacy toggle; release builds shrink unused resources.
  • Warnings before executable or disguised downloads; internationalized domains display as punycode; optional referrer trimming on navigations.
  • CI checks dependency integrity, secrets and the manifest; the browsing database encrypts at rest; toolchains pinned for reproducible builds.
  • Navigations send Do Not Track and Global Privacy Control signals; POST forms no longer lose their body when privacy headers are enabled.

Two engines

  • The browser core sits behind a real engine seam — the WebView build ships as Arktos Light, a GeckoView build as Arktos (arm64).
  • GeckoView parity: navigation policy, SSL errors, tab state, prompts, downloads, storage/cookies, proxy/I2P and userscripts.

Gecko engine hardening (v1.0 maintenance)

  • Tab switching reworked around one shared GeckoView (the mozilla-components model) — per-tab views lost their compositor surface on detach and painted black; the shared view binds sessions in place.
  • The shared view releases its session before any window detach so GeckoView can't auto-close it — the root cause of dead/frozen tabs when swapping to generated pages or entering fullscreen.
  • Killed content processes recover via onKill/onCrash handling — dead sessions re-open and re-apply their saved state on next select.
  • Tab restore hardened end to end: URL fallback per tab, a plain-URL list when the parcel is unreadable, and engine state restored first so scroll and history survive.
  • Site permission decisions (geolocation, notifications, camera/mic) persist per origin for regular tabs — prompts no longer repeat on tab switches or restarts; incognito keeps them memory-only.
  • Generated chrome pages (arktos://changelog, start/bookmark/history pages) serve as data loads with artwork inlined — no more missing logos or stalled chrome pages.
  • Startup fix: engine init runs only in browser processes — GeckoView's child service processes no longer race the main profile.
  • Text reflow on gecko rides the bundled userscript WebExtension — driven by visualViewport with a live toggle.
  • DuckDuckGo is now the default search engine and suggestions provider.

Incognito hardening

  • The incognito data partition is wiped when the session ends and on fresh start — cookies and logins can't carry between private sessions.
  • Panic clean covers the incognito profile; the private-tabs reminder stays off the lock screen; incognito typing doesn't feed keyboard learning.

Modernization

  • Deprecated APIs swept out: file picking, permissions and activity results use modern contracts; camera uploads use safe FileProvider URIs.
  • Dead code removed: old preference-activity wrappers, the reflection-based permissions framework, duplicate animators.
